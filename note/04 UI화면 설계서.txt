| 권한 레벨 | 접근 가능 화면 | 비고 |
| --- | --- | --- |
| **공개(비로그인)** | 로그인, 회원가입 | 그 외 모든 경로는 `/login`으로 리다이렉트 |

## 2. 전체 레이아웃 구조

### 2.1 공통 레이아웃 (로그인 후)

```
┌────────────┬──────────────────────────────────────────────────────────┐
│            │  PageHeader                                              │
│  Sidebar   │  [페이지 제목 / 서브타이틀]   [검색]      [사용자 프로필] │
│            ├──────────────────────────────────────────────────────────┤
│ [로고]     │                                                          │
│            │                                                          │
│ ● 홈       │                                                          │
│ ● 코드분석 │                  Main Content Area                       │
│ ● 분석결과 │                  (각 페이지 내용)                         │
│            │                                                          │
│ [검색]     │                                                          │
│ [필터칩]   │                                                          │
│            │                                                          │
│ ⭐즐겨찾기 │                                                          │
│  · 프로젝트│                                                          │
│ 🗂 보관됨  │                                                          │
│ + 프로젝트 │                                                          │
│   추가     │                                                          │
└────────────┴──────────────────────────────────────────────────────────┘
```

- 좌측 **Sidebar는 고정 폭(약 240px)**, 모든 로그인 화면에서 항상 표시된다.
- 로그인/회원가입 화면은 Sidebar 없이 **중앙 단일 카드 레이아웃**을 사용한다.
- Footer는 두지 않는다 (작업 도구 성격의 화면이므로 세로 공간을 콘텐츠에 사용).

### 2.2 공통 컴포넌트 목록

| 컴포넌트명 | 위치 | 역할 | 항상 표시 |
| --- | --- | --- | --- |
| `Sidebar` | 좌측 고정 | 로고, 주 네비게이션, 프로젝트(분석) 목록, ~~필터(없는걸로 확정)~~ | 로그인 화면 전체 |
| `PageHeader` | 상단 | 페이지 제목·서브타이틀, 우측 액션 버튼, 사용자 프로필 | 로그인 화면 전체 |
| `FileTree` | 콘텐츠 좌측 | 분석 대상 파일 트리 (취약점 표시 점 포함) | SCR-002 / SCR-003 |
| `CodeViewer` | 콘텐츠 중앙 | 라인 번호 + 구문 하이라이트 + 취약 라인 마커 | SCR-002 / SCR-003 |
| `SeverityBadge` | 목록·상세 | 심각도 배지 (치명적/높음/중간/낮음) | 상황별 |
| `LoadingSpinner` | 콘텐츠 영역 | 데이터 로딩 표시 | 상황별 |
| `EmptyState` | 콘텐츠 영역 | 데이터 없음 안내 + 유도 버튼 | 상황별 |
| `ErrorMessage` | 콘텐츠 영역 | 오류 안내 + 재시도 버튼 | 상황별 |
| `Toast` | 우상단 | 성공/실패 알림 | 상황별 |

### 2.3 심각도 표기 규칙 (전 화면 공통)

| 심각도 | 표기 | Enum | 용도 |
| --- | --- | --- | --- |
| 치명적 | ● 진한 빨강 | `CRITICAL` | 즉시 조치 필요 |
| 높음 | ● 주황 | `HIGH` | 우선 조치 |
| 중간 | ● 노랑 | `MEDIUM` | 계획적 조치 |
| 낮음 | ○ 연두 | `LOW` | 참고 |

> 색상만으로 구분하지 않고 **반드시 텍스트 라벨을 함께 표기**한다 (색각 이상 사용자 고려).

#### 3.1.4 화면 상태 목록

#### 3.1.5 사용자 인터랙션 흐름

```
[페이지 진입]
    → GET /api/v1/dashboard/summary?days=30
    → 지표 4종 + 차트 + 최근 분석 목록 렌더링

[코드 가져오기 시작 클릭]
    → navigate('/analysis/new')

[최근 분석 행 클릭]
    → 상태가 COMPLETED → navigate(`/analyses/${analysisId}`)
    → 상태가 SCANNING/EXPLAINING → navigate(`/analysis/new?resume=${analysisId}`) (진행 화면)
    → 상태가 FAILED     → "분석에 실패한 항목입니다" 토스트

[전체 보기 클릭]
    → navigate('/analyses')

[사이드바 프로젝트 클릭]
    → navigate(`/analyses/${analysisId}`)
```

#### 3.2.3 UI 컴포넌트 매핑

| 화면 요소 | React 컴포넌트 | 구현 방식 | 비고 |
| --- | --- | --- | --- |
| 파일 탐색기 | `FileTree` | 자체 구현 (재귀 렌더링) | `relativePath`를 `/`로 분해해 트리 구성 |
| 코드 편집/뷰어 | `CodeEditor` | `<textarea>` + 라인번호 오버레이 | MVP는 구문 하이라이트 없이 시작, 여유 시 추가 |
| 파일 추가 버튼 | `AddFileButton` | 자체 구현 | 파일명 입력 → 빈 파일 추가 |

#### 3.5.1 화면 개요

| 항목 | 로그인 | 회원가입 |
| --- | --- | --- |
| **URL** | `/login` | `/signup` |
| **화면 타입** | 입력 | 입력 |
| **권한 레벨** | 공개 | 공개 |
| **주요 기능** | 이메일·비밀번호 로그인 | 이메일·비밀번호 가입 |
| **연결 API** | `POST /api/v1/auth/login` | `POST /api/v1/auth/signup` |

#### 3.5.2 와이어프레임 (ASCII)

```
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│                    ◼ CodeGuard AI                            │
│         배포 전에, 코드 속 위험을 먼저 발견하세요              │
│                                                              │
│            ┌────────────────────────────────┐                │
│            │ 이메일                          │                │
│            │ [ dev@codeguard.dev          ] │                │
│            │                                │                │
│            │ 비밀번호                        │                │
│            │ [ ••••••••••                 ] │                │
│            │                                │                │
│            │ ⚠ 이메일 또는 비밀번호가        │                │
│            │   올바르지 않습니다             │                │
│            │                                │                │
│            │ [        로그인            ]   │                │
│            │                                │                │
│            │ 계정이 없으신가요? 회원가입      │                │
│            └────────────────────────────────┘                │
└──────────────────────────────────────────────────────────────┘
```

#### 3.5.3 화면 상태 목록

| 상태 | 표시 내용 | 트리거 |
| --- | --- | --- |
| **입력 중** | 버튼 활성화 (이메일·비밀번호 모두 입력 시) | onChange |
| **검증 실패** | 필드 하단 에러 (이메일 형식, 비밀번호 8자 이상) | 제출 시 클라이언트 검증 |
| **제출 중** | 버튼 로딩, 중복 제출 차단 | API 호출 중 |
| **로그인 실패** | "이메일 또는 비밀번호가 올바르지 않습니다" | 401 응답 |
| **이메일 중복** | "이미 사용 중인 이메일입니다" | 409 응답 (회원가입) |
| **성공** | 토큰 저장 후 `/`로 이동 (회원가입은 `/login`으로) | 200/201 |

#### 3.5.4 사용자 인터랙션 흐름

```
[로그인 제출]
    → POST /api/v1/auth/login { email, password }
    → 성공: authStore.setToken(accessToken) → navigate('/')
    → 실패: 폼 상단에 에러 메시지 (필드별로 나누지 않음 — 계정 존재 여부 노출 방지)

[회원가입 제출]
    → POST /api/v1/auth/signup
    → 성공: "회원가입이 완료되었습니다" 토스트 → navigate('/login')
    → 409: "이미 사용 중인 이메일입니다"
```

## 4. 네비게이션 흐름도

```
[로그인 /login]
    │  성공
    ▼
[홈 /]  ◀──────────────────────────────────┐
    │                                       │
    ├── [코드 가져오기 시작]                 │
    │        ▼                              │
    │   [코드 분석 /analysis/new]            │
    │        │  분석 시작 → 202 → 폴링       │
    │        │  COMPLETED                    │
    │        ▼                              │
    ├── [취약점 분석 결과 /analyses/:id] ────┤
    │        ├── [보고서 내보내기] → 파일 다운로드
    │        ├── [해결/무시 처리] → 상태 변경
    │        └── [다시 분석] → /analysis/new
    │                                        │
    ├── [전체 보기] ▶ [분석 결과 목록 /analyses]
    │                      └── 행 클릭 → /analyses/:id
    │                      └── 삭제 → 목록 갱신
    │                                        │
    └── [사이드바 프로젝트 클릭] ────────────┘

[비로그인 상태로 보호된 경로 접근]
    → /login 리다이렉트 (이전 경로 기억 후 로그인 시 복귀)
```
