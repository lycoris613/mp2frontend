| HTTP 상태 | 의미 | 처리 방식 |
| --- | --- | --- |
| `400` | 검증 오류 | `fieldErrors`를 해당 입력 필드 하단에 표시 |
| `401` | 인증 실패/만료 | 토큰 삭제 → `/login` 이동 |
| `403` | 권한 없음 | "해당 분석에 접근할 권한이 없습니다" 토스트 + 홈 이동 |
| `404` | 리소스 없음 | "분석을 찾을 수 없습니다" 화면 표시 |
| `409` | 중복/상태 충돌 | "이미 해결 처리된 취약점입니다" 등 토스트 |
| `413` | 크기 초과 | "전체 코드 크기가 500KB를 초과했습니다" 폼 상단 표시 |
| `422` | 규칙 위반 | "진행 중인 분석은 삭제할 수 없습니다" 토스트 |
| `502` | LLM 오류 | "AI 분석 서비스에 연결하지 못했습니다. 다시 시도해 주세요" + 재시도 버튼 |
| `500` | 서버 오류 | "서버 오류. 잠시 후 다시 시도해 주세요" |

| 최적화 기법 | 적용 대상 | 사용 이유 |

| `useMemo` | `visibleFindings`, `markers` (FindingResultPage) | 탭 전환마다 수십~수백 건 배열을 필터링하므로 재계산을 막는다 |
| `useMemo` | `buildFileTree(files)` (FileTree 내부) | 경로 배열 → 트리 변환은 렌더마다 반복할 필요가 없다 |

| `useCallback` | `handleSelectFile`, `handleCodeChange` | memo 된 자식에게 내려주는 콜백의 참조 고정 |
| 로컬 상태 유지 | `draftFiles` (전역화 금지) | 타이핑마다 전역 스토어가 갱신되면 사이드바까지 리렌더된다 |
