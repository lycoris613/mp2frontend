## 1. Entity 설계 개요

### 1.1 설계 목적

> JPA Entity 클래스 설계를 통해 객체-관계 매핑(ORM)을 정의하고,
"사용자 → 분석 요청 → 파일 → 취약점 → LLM 분석"의 도메인 계층을 코드로 표현하여
**Scanner(탐지) → LLM(설명)** 2단계 파이프라인이 안정적으로 데이터를 적재할 수 있는 구조를 구축한다.
> 
> 
> 쓰기 주체가 단계별로 다르다는 점이 본 설계의 핵심이다.
> 
> - `AnalysisFile` : 사용자 입력으로 생성
> - `FindingVulnerability` : **Security Scanner가 생성** (LLM은 수정 불가)
> - `LlmAnalysis` : **LLM 모듈이 생성** (탐지 결과를 변경하지 않음)

### 1.2 설계 원칙

- **단일 책임 원칙**: 하나의 Entity는 하나의 비즈니스 개념만 표현한다
- **캡슐화**: 상태 전이(분석 시작/완료/실패, 취약점 해결/무시)는 Entity 메서드로만 수행하고 Setter를 열지 않는다
- **Aggregate 경계 준수**: `AnalysisRequest`가 Root이며, 하위 Entity는 Root를 통해 생성한다
- **연관관계 최소화**: 역방향(@OneToMany)은 실제로 함께 조회·삭제되는 경우에만 매핑한다
- **대용량 컬럼 분리 의식**: 코드 본문·LLM 원문 등 MEDIUMTEXT 컬럼은 목록 조회 시 로딩하지 않는다

### 1.3 기술 스택

- **프레임워크**: Spring Boot 4.0.8 (Java 17)
- **ORM**: Spring Data JPA (Hibernate)
- **데이터베이스**: MariaDB 10.11 (`jdbc:mariadb://.../lab_db`)
- **검증 프레임워크**: Jakarta Bean Validation (`spring-boot-starter-validation`)
- **감사 기능**: Spring Data JPA Auditing
- **빌드**: Maven (`com.rookies6` / `MySpringBoot4Project`)
- **패키지 루트(제안)**: `com.rookies6.codeguard`

## 2. Entity 목록 및 분류

### 2.1 Entity 분류 매트릭스

| Entity명 | 유형 | 비즈니스 중요도 | 기술적 복잡도 | 우선순위 | 담당 |
| --- | --- | --- | --- | --- | --- |
| **User** | 핵심 | 높음 | 낮음 | 1순위 | Backend |
| **AnalysisRequest** | 핵심 | 높음 | 높음 (상태 전이·비동기) | 1순위 | Backend |
| **AnalysisFile** | 핵심 | 높음 | 중간 (대용량 컬럼) | 1순위 | Backend |
| **FindingVulnerability** | 핵심 | 높음 | 중간 | 1순위 | Security (Scanner가 생성) |
| **LlmAnalysis** | 핵심 | 높음 | 중간 (1:1, 토큰 집계) | 1순위 | LLM |

### 2.2 Entity 상속 구조

모든 Entity는 `BaseEntity`(`id`, `createdAt`, `updatedAt`)를 상속한다.
단, `FindingVulnerability`는 ERD상 `updated_at`이 없으나 **처리 상태(status)가 변경되는 Entity이므로 BaseEntity를 동일하게 상속**하여 수정 시각을 남긴다.

```
BaseEntity (@MappedSuperclass)
 ├── User
 ├── AnalysisRequest
 ├── AnalysisFile
 ├── FindingVulnerability
 └── LlmAnalysis
```

### 2.3 테이블 매핑 요약

| Entity | 테이블명 | 예상 행 수(MVP) | 대용량 컬럼 |
| --- | --- | --- | --- |
| User | `users` | 수십 | — |
| AnalysisRequest | `analysis_request` | 수백 | — |
| AnalysisFile | `analysis_file` | 수천 | `content` (MEDIUMTEXT) |
| FindingVulnerability | `finding_vulnerability` | 수천 | `code_snippet` (TEXT) |
| LlmAnalysis | `llm_analysis` | 수천 | `raw_response` (MEDIUMTEXT), TEXT 5종 |

## 3. 공통 설계 규칙

### 3.1 네이밍 규칙

| 구분 | 규칙 | 예시 | 비고 |
| --- | --- | --- | --- |
| **Entity 클래스명** | PascalCase | `AnalysisRequest`, `LlmAnalysis` | 단수형 사용 |
| **테이블명** | snake_case | `analysis_request`, `llm_analysis` | ERD 표기를 그대로 따름(단수형) |
| **컬럼명** | snake_case | `analysis_file_id`, `created_at` | 언더스코어 구분 |
| **연관관계 필드** | camelCase | `analysisFiles`, `llmAnalysis` | 객체 참조명 |
| **Enum 상수** | UPPER_SNAKE | `SQL_INJECTION`, `IN_PROGRESS` | STRING으로 저장 |
| **boolean 필드** | is + 형용사 | `isResolved` | 메서드는 `isXxx()` |

> ⚠️ **팀 합의 필요**: 템플릿은 테이블 복수형(`members`)을 권장하나, ERD는 단수형(`analysis_request`)으로 되어 있다.
본 문서는 **ERD 표기(단수형)** 를 따르고 `users`만 예약어 회피를 위해 복수형을 유지한다.
(MariaDB에서 `user`는 시스템 테이블명과 충돌 소지가 있음)
> 

### 3.2 공통 어노테이션 규칙

```java
@Entity
@Table(name = "테이블명")
@NoArgsConstructor(access = AccessLevel.PROTECTED)
@Getter
public class EntityName extends BaseEntity {
    // 필드 정의
    // Setter 금지 — 상태 변경은 의미 있는 메서드로만
}
```

### 3.3 ID 생성 전략

| Entity | 전략 | 이유 |
| --- | --- | --- |
| **User** | IDENTITY | MariaDB Auto Increment 활용 |
| **AnalysisRequest** | IDENTITY | 요청 순서 보장 |
| **AnalysisFile** | IDENTITY | 대량 삽입 단순화 |
| **FindingVulnerability** | IDENTITY | 탐지 순서 보장 |
| **LlmAnalysis** | IDENTITY | 단순 증가 |

> 취약점·LLM 결과는 한 분석에서 수십 건이 한 번에 저장된다.
IDENTITY 전략은 JDBC batch insert가 비활성화되므로, 성능 이슈 발생 시 §8.3 대량 삽입 전략을 적용한다.
> 

### 3.4 컬럼 길이 규칙

| 용도 | 타입 | 길이 | 예시 |
| --- | --- | --- | --- |
| 식별자성 짧은 문자열 | VARCHAR | 20 | `status`, `severity`, `language`, `cwe_id` |
| 이름·유형 | VARCHAR | 50~100 | `file_name`, `vulnerability_type`, `model_name` |
| 경로 | VARCHAR | 500 | `relative_path` |
| 메시지 | VARCHAR | 500 | `error_message` |
| 코드 조각·설명 | TEXT | — | `code_snippet`, `explanation`, `fixed_code` |
| 코드 본문·LLM 원문 | MEDIUMTEXT | — | `content`, `raw_response` |

```java
@Entity
@Table(name = "users",
       uniqueConstraints = @UniqueConstraint(name = "uk_users_email", columnNames = "email"))
@NoArgsConstructor(access = AccessLevel.PROTECTED)
@Getter
public class User extends BaseEntity {

    @Column(nullable = false, unique = true, length = 100)
    @Email(message = "이메일 형식이 올바르지 않습니다")
    @NotBlank(message = "이메일은 필수입니다")
    private String email;

    @Column(nullable = false, length = 255)
    @NotBlank(message = "비밀번호는 필수입니다")
    private String password;   // 항상 암호화된 값만 들어온다

    // 정적 팩토리 — 암호화는 Service에서 수행 후 전달
    public static User create(String email, String encodedPassword) {
        User user = new User();
        user.email = email;
        user.password = encodedPassword;
        return user;
    }

    public void changePassword(String encodedPassword) {
        this.password = encodedPassword;
    }

    public boolean owns(AnalysisRequest request) {
        return request.getUser().getId().equals(this.getId());
    }
}
```

### 4.2 AnalysisRequest Entity

#### 4.2.1 필드 상세 명세

| 필드명 | 데이터 타입 | 컬럼명 | 제약조건 | 설명 | 비즈니스 규칙 |
| --- | --- | --- | --- | --- | --- |
| **id** | `Long` | `id` | PK, AUTO_INCREMENT | 분석요청 식별자 | — |
| **user** | `User` | `user_id` | FK, NOT NULL | 요청자 | 본인만 조회 (BR-U004) |
| **title** | `String` | `title` | NOT NULL, LENGTH(100) | 분석 제목(프로젝트명) | 화면 상단에 표시 |
| **status** | `AnalysisStatus` | `status` | NOT NULL, ENUM(20) | 분석 상태 | PENDING/SCANNING/EXPLAINING/COMPLETED/FAILED (BR-A004) |
| **totalFiles** | `Integer` | `total_files` | NOT NULL, DEFAULT 0 | 대상 파일 수 | 1~20 (BR-A002) |
| **totalFindings** | `Integer` | `total_findings` | NOT NULL, DEFAULT 0 | 취약점 개수 | 완료 시 집계 |
| **errorMessage** | `String` | `error_message` | NULL 허용, LENGTH(500) | 실패 사유 | FAILED일 때만 |
| **startedAt** | `LocalDateTime` | `started_at` | NULL 허용 | 분석 시작 시각 | SCANNING 전환 시 |
| **completedAt** | `LocalDateTime` | `completed_at` | NULL 허용 | 분석 종료 시각 | COMPLETED/FAILED 시 |

#### 4.2.2 구현 코드 예시

```java
@Entity
@Table(name = "analysis_request",
       indexes = {
           @Index(name = "idx_ar_user_created", columnList = "user_id, created_at"),
           @Index(name = "idx_ar_status", columnList = "status")
       })
@NoArgsConstructor(access = AccessLevel.PROTECTED)
@Getter
public class AnalysisRequest extends BaseEntity {

    @ManyToOne(fetch = FetchType.LAZY, optional = false)
    @JoinColumn(name = "user_id", nullable = false)
    private User user;

    @Column(nullable = false, length = 100)
    @NotBlank(message = "분석 제목은 필수입니다")
    @Size(max = 100)
    private String title;

    @Enumerated(EnumType.STRING)
    @Column(nullable = false, length = 20)
    private AnalysisStatus status = AnalysisStatus.PENDING;

    @Enumerated(EnumType.STRING)
    @Column(name = "overall_severity", length = 20)
    private Severity overallSeverity;

    @Column(name = "total_files", nullable = false)
    private Integer totalFiles = 0;

    @Column(name = "total_findings", nullable = false)
    private Integer totalFindings = 0;

    @Column(name = "error_message", length = 500)
    private String errorMessage;

    @Column(name = "started_at")
    private LocalDateTime startedAt;

    @Column(name = "completed_at")
    private LocalDateTime completedAt;

    @OneToMany(mappedBy = "analysisRequest",
               cascade = CascadeType.ALL, orphanRemoval = true,
               fetch = FetchType.LAZY)
    @OrderBy("relativePath ASC")
    private List<AnalysisFile> analysisFiles = new ArrayList<>();

    // ── 생성 ────────────────────────────────────────────
    public static AnalysisRequest create(User user, String title) {
        AnalysisRequest request = new AnalysisRequest();
        request.user = user;
        request.title = title;
        request.status = AnalysisStatus.PENDING;
        return request;
    }

    // ── 연관관계 편의 메서드 ────────────────────────────
    public void addFile(AnalysisFile file) {
        if (analysisFiles.size() >= 20) {
            throw new BusinessException(ErrorCode.FILE_COUNT_EXCEEDED);   // BR-A002
        }
        boolean duplicated = analysisFiles.stream()
                .anyMatch(f -> f.getRelativePath().equals(file.getRelativePath()));
        if (duplicated) {
            throw new BusinessException(ErrorCode.DUPLICATE_FILE_PATH);   // BR-A009
        }
        analysisFiles.add(file);
        file.assignTo(this);
        this.totalFiles = analysisFiles.size();
    }

    // ── 상태 전이 (BR-A004) ─────────────────────────────
    /** PENDING → SCANNING : Scanner 단계 시작 */
    public void startScanning() {
        if (this.status != AnalysisStatus.PENDING) {
            throw new BusinessException(ErrorCode.INVALID_ANALYSIS_STATUS);
        }
        this.status = AnalysisStatus.SCANNING;
        this.startedAt = LocalDateTime.now();
    }

    /** SCANNING → EXPLAINING : 탐지 완료, LLM 설명 단계 시작 */
    public void startExplaining(int totalFindings) {
        if (this.status != AnalysisStatus.SCANNING) {
            throw new BusinessException(ErrorCode.INVALID_ANALYSIS_STATUS);
        }
        this.totalFindings = totalFindings;
        this.status = AnalysisStatus.EXPLAINING;
    }

    /** EXPLAINING → COMPLETED (탐지 0건이면 SCANNING 에서 바로 완료, BR-A006) */
    public void complete(Severity overallSeverity) {
        if (this.status != AnalysisStatus.EXPLAINING && this.status != AnalysisStatus.SCANNING) {
            throw new BusinessException(ErrorCode.INVALID_ANALYSIS_STATUS);
        }
        this.status = AnalysisStatus.COMPLETED;
        this.overallSeverity = overallSeverity;
        this.completedAt = LocalDateTime.now();
    }

    public void fail(String message) {
        this.status = AnalysisStatus.FAILED;
        this.errorMessage = truncate(message, 500);
        this.completedAt = LocalDateTime.now();
    }

    // ── 조회용 ──────────────────────────────────────────
    public boolean isInProgress() {
        return status.isInProgress();
    }

    public Long getDurationSeconds() {
        if (startedAt == null || completedAt == null) return null;
        return Duration.between(startedAt, completedAt).toSeconds();
    }

    private static String truncate(String s, int max) {
        if (s == null) return null;
        return s.length() <= max ? s : s.substring(0, max);
    }
}
```

### 4.3 AnalysisFile Entity

#### 4.3.1 필드 상세 명세

| 필드명 | 데이터 타입 | 컬럼명 | 제약조건 | 설명 | 비즈니스 규칙 |
| --- | --- | --- | --- | --- | --- |
| **id** | `Long` | `id` | PK, AUTO_INCREMENT | 파일 식별자 | — |
| **analysisRequest** | `AnalysisRequest` | `analysis_request_id` | FK, NOT NULL | 소속 분석 요청 | Cascade 삭제 |
| **relativePath** | `String` | `relative_path` | NOT NULL, LENGTH(500) | 상대 경로 | 요청 내 UNIQUE (BR-A009) |
| **fileName** | `String` | `file_name` | NOT NULL, LENGTH(255) | 파일명 | 경로에서 추출 |
| **extension** | `String` | `extension` | NOT NULL, LENGTH(20) | 확장자 | 언어 판별용 |
| **language** | `Language` | `language` | NOT NULL, ENUM(20) | 코드 언어 | 확장자 기반 자동 판별 |
| 🆕 **content** | `String` | `content` | NOT NULL, MEDIUMTEXT | 코드 본문 | **ver2 ERD 누락 — 추가 필수 (D-02)** |
| **fileSizeBytes** | `Integer` | `file_size_bytes` | NOT NULL | 파일 크기 | 최대 102,400 (BR-A003) |

#### 4.3.2 구현 코드 예시

```java
@Entity
@Table(name = "analysis_file",
       uniqueConstraints = @UniqueConstraint(
           name = "uk_af_request_path",
           columnNames = {"analysis_request_id", "relative_path"}),
       indexes = @Index(name = "idx_af_request", columnList = "analysis_request_id"))
@NoArgsConstructor(access = AccessLevel.PROTECTED)
@Getter
public class AnalysisFile extends BaseEntity {

    @ManyToOne(fetch = FetchType.LAZY, optional = false)
    @JoinColumn(name = "analysis_request_id", nullable = false)
    private AnalysisRequest analysisRequest;

    @Column(name = "relative_path", nullable = false, length = 500)
    @NotBlank private String relativePath;

    @Column(name = "file_name", nullable = false, length = 255)
    private String fileName;

    @Column(nullable = false, length = 20)
    private String extension;

    @Enumerated(EnumType.STRING)
    @Column(nullable = false, length = 20)
    private Language language;

    /* 코드 본문 — 목록 조회 시 불필요하므로 지연 로딩한다.
       (하이버네이트 바이트코드 인핸스먼트 미적용 환경에서는 무시되므로,
        목록 조회는 반드시 DTO Projection 을 사용한다. §8.2 참조) */
    @Lob
    @Basic(fetch = FetchType.LAZY)
    @Column(nullable = false, columnDefinition = "MEDIUMTEXT")
    private String content;

    @Column(name = "file_size_bytes", nullable = false)
    @Max(value = 102_400, message = "파일은 100KB를 초과할 수 없습니다")
    private Integer fileSizeBytes;

    @OneToMany(mappedBy = "analysisFile",
               cascade = CascadeType.ALL, orphanRemoval = true,
               fetch = FetchType.LAZY)
    @OrderBy("startLine ASC")
    private List<FindingVulnerability> findings = new ArrayList<>();

    public static AnalysisFile of(String relativePath, String content) {
        AnalysisFile file = new AnalysisFile();
        file.relativePath = relativePath;
        file.fileName = relativePath.substring(relativePath.lastIndexOf('/') + 1);
        file.extension = extractExtension(file.fileName);
        file.language = Language.fromExtension(file.extension);
        file.content = content;
        file.fileSizeBytes = content.getBytes(StandardCharsets.UTF_8).length;
        return file;
    }

    void assignTo(AnalysisRequest request) {   // package-private: Root 를 통해서만 호출
        this.analysisRequest = request;
    }

    public void addFinding(FindingVulnerability finding) {
        findings.add(finding);
        finding.assignTo(this);
    }

    public int getLineCount() {
        return content.split("\n", -1).length;
    }

    /** Before/After 화면용 코드 구간 추출 (1-based, 양끝 포함) */
    public String extractSnippet(int startLine, int endLine) {
        String[] lines = content.split("\n", -1);
        int from = Math.max(1, startLine);
        int to   = Math.min(lines.length, endLine);
        return String.join("\n", Arrays.copyOfRange(lines, from - 1, to));
    }

    private static String extractExtension(String fileName) {
        int idx = fileName.lastIndexOf('.');
        return idx < 0 ? "" : fileName.substring(idx + 1).toLowerCase();
    }
}
```

#### 4.4.2 구현 코드 예시

```java
@Entity
@Table(name = "finding_vulnerability",
       indexes = {
           @Index(name = "idx_fv_file", columnList = "analysis_file_id"),
           @Index(name = "idx_fv_severity", columnList = "severity"),
           @Index(name = "idx_fv_type", columnList = "vulnerability_type"),
           @Index(name = "idx_fv_rule", columnList = "rule_id")
       })
@NoArgsConstructor(access = AccessLevel.PROTECTED)
@Getter
public class FindingVulnerability extends BaseEntity {

    @ManyToOne(fetch = FetchType.LAZY, optional = false)
    @JoinColumn(name = "analysis_file_id", nullable = false)
    private AnalysisFile analysisFile;

    /* 어느 룰이 탐지했는지 — 오탐 개선·룰 튜닝의 근거가 되므로 반드시 저장한다 */
    @Column(name = "rule_id", nullable = false, length = 50)
    private String ruleId;

    @Enumerated(EnumType.STRING)
    @Column(name = "vulnerability_type", nullable = false, length = 50)
    private VulnerabilityType vulnerabilityType;

    @Column(name = "cwe_id", nullable = false, length = 20)
    @Pattern(regexp = "^CWE-\\d{1,5}$", message = "CWE 형식이 올바르지 않습니다")
    private String cweId;

    @Enumerated(EnumType.STRING)
    @Column(nullable = false, length = 20)
    private Severity severity;

    @Enumerated(EnumType.STRING)
    @Column(nullable = false, length = 20)
    private FindingStatus status = FindingStatus.OPEN;

    @Column(name = "start_line", nullable = false)
    @Min(1) private Integer startLine;

    @Column(name = "end_line", nullable = false)
    @Min(1) private Integer endLine;

    @Column(name = "code_snippet", nullable = false, columnDefinition = "TEXT")
    private String codeSnippet;

    @OneToOne(mappedBy = "finding",
              cascade = CascadeType.ALL, orphanRemoval = true,
              fetch = FetchType.LAZY)
    private LlmAnalysis llmAnalysis;

    /** Scanner 전용 생성자 — 취약점은 오직 룰 매칭으로만 만들어진다 (BR-S001) */
    public static FindingVulnerability fromRule(SecurityRule rule,
                                                int startLine, int endLine, String codeSnippet) {
        if (startLine > endLine) {
            throw new BusinessException(ErrorCode.INVALID_LINE_RANGE);   // BR-S012
        }
        FindingVulnerability f = new FindingVulnerability();
        f.ruleId            = rule.getRuleId();
        f.vulnerabilityType = rule.getVulnerabilityType();
        f.cweId             = rule.getCweId();
        f.severity          = rule.getSeverity();
        f.startLine         = startLine;
        f.endLine           = endLine;
        f.codeSnippet       = codeSnippet;
        f.status            = FindingStatus.OPEN;
        return f;
    }

    void assignTo(AnalysisFile file) { this.analysisFile = file; }

    public void attachLlmAnalysis(LlmAnalysis analysis) {
        this.llmAnalysis = analysis;
        analysis.assignTo(this);
    }

    // ── 상태 전이 ───────────────────────────────────────
    public void resolve() {
        if (this.status == FindingStatus.RESOLVED) {
            throw new BusinessException(ErrorCode.ALREADY_RESOLVED);
        }
        this.status = FindingStatus.RESOLVED;
    }

    public void ignore() {                   // 오탐 처리
        this.status = FindingStatus.IGNORED;
    }

    public void reopen() {
        this.status = FindingStatus.OPEN;
    }

    public boolean isCritical() { return severity == Severity.CRITICAL; }

    // ── Scanner 후처리 ──────────────────────────────────
    /** 같은 룰이 연속 라인에서 매칭된 경우 하나의 구간으로 병합 (BR-S009) */
    public void mergeWith(FindingVulnerability other) {
        if (!this.ruleId.equals(other.ruleId)) {
            throw new IllegalArgumentException("다른 룰의 탐지 결과는 병합할 수 없습니다");
        }
        this.startLine   = Math.min(this.startLine, other.startLine);
        this.endLine     = Math.max(this.endLine, other.endLine);
        this.codeSnippet = analysisFile.extractSnippet(this.startLine, this.endLine);
    }

    /** 테스트 파일에서 탐지된 경우 심각도 1단계 하향 (BR-S007) */
    public void downgradeSeverity() {
        this.severity = severity.downgrade();
    }

    public String getLineRange() {
        return startLine.equals(endLine) ? String.valueOf(startLine)
                                         : startLine + "-" + endLine;
    }

    @PrePersist @PreUpdate
    private void validate() {
        if (startLine > endLine) {
            throw new IllegalArgumentException("시작 라인은 끝 라인보다 클 수 없습니다");
        }
    }
}
```

#### 4.5.2 구현 코드 예시

```java
@Entity
@Table(name = "llm_analysis",
       uniqueConstraints = @UniqueConstraint(
           name = "uk_llm_finding", columnNames = "finding_id"))
@NoArgsConstructor(access = AccessLevel.PROTECTED)
@Getter
public class LlmAnalysis extends BaseEntity {

    @OneToOne(fetch = FetchType.LAZY, optional = false)
    @JoinColumn(name = "finding_id", nullable = false, unique = true)
    private FindingVulnerability finding;

    @Enumerated(EnumType.STRING)
    @Column(nullable = false, length = 20)
    private LlmAnalysisStatus status = LlmAnalysisStatus.PENDING;

    @Column(columnDefinition = "TEXT") private String explanation;
    @Column(name = "risk_description", columnDefinition = "TEXT") private String riskDescription;
    @Column(name = "attack_scenario",  columnDefinition = "TEXT") private String attackScenario;
    @Column(columnDefinition = "TEXT") private String remediation;
    @Column(name = "fixed_code",       columnDefinition = "TEXT") private String fixedCode;

    /* 탐지는 룰이 했으므로, LLM 은 "이 탐지가 진짜인가"를 판정만 한다.
       판정 결과로 Finding 을 삭제하지 않는다 (BR-L008). */
    @Enumerated(EnumType.STRING)
    @Column(length = 20) private LlmVerdict verdict;

    @Column @Min(0) @Max(100) private Integer confidence;

    @Column(name = "model_name", length = 100)    private String modelName;
    @Column(name = "prompt_version", length = 30) private String promptVersion;

    @Lob
    @Basic(fetch = FetchType.LAZY)
    @Column(name = "raw_response", columnDefinition = "MEDIUMTEXT")
    private String rawResponse;

    @Column(name = "prompt_tokens")     private Integer promptTokens;
    @Column(name = "completion_tokens") private Integer completionTokens;
    @Column(name = "error_message", length = 500) private String errorMessage;

    public static LlmAnalysis success(LlmResultDto dto, LlmMeta meta) {
        LlmAnalysis a = new LlmAnalysis();
        a.status           = LlmAnalysisStatus.SUCCESS;
        a.explanation      = dto.explanation();
        a.riskDescription  = dto.riskDescription();
        a.attackScenario   = dto.attackScenario();
        a.remediation      = dto.remediation();
        a.fixedCode        = dto.fixedCode();
        a.verdict          = LlmVerdict.from(dto.verdict());
        a.confidence       = dto.confidence();
        a.modelName        = meta.modelName();
        a.promptVersion    = meta.promptVersion();
        a.rawResponse      = meta.rawResponse();
        a.promptTokens     = meta.promptTokens();
        a.completionTokens = meta.completionTokens();
        return a;
    }

    public static LlmAnalysis failed(String rawResponse, String errorMessage, LlmMeta meta) {
        LlmAnalysis a = new LlmAnalysis();
        a.status       = LlmAnalysisStatus.FAILED;
        a.rawResponse  = rawResponse;          // 실패해도 원문은 남긴다 (BR-L006)
        a.errorMessage = errorMessage;
        a.modelName    = meta.modelName();
        a.promptVersion = meta.promptVersion();
        return a;
    }

    void assignTo(FindingVulnerability finding) { this.finding = finding; }

    public int getTotalTokens() {
        return (promptTokens == null ? 0 : promptTokens)
             + (completionTokens == null ? 0 : completionTokens);
    }

    public boolean hasFixedCode() {
        return fixedCode != null && !fixedCode.isBlank();
    }

    /** 화면에 "오탐 가능성 있음" 배지를 띄울지 판단 */
    public boolean isLikelyFalsePositive() {
        return verdict == LlmVerdict.FALSE_POSITIVE
            || (confidence != null && confidence < 50);
    }

    public boolean isSuccess() { return status == LlmAnalysisStatus.SUCCESS; }
}
```

### 4.6 SecurityRule (Entity 아님 — 참고)

Scanner가 사용하는 룰은 **DB 테이블이 아니라 코드 상수**다 (BR-S003, D-17).
`FindingVulnerability.ruleId`는 이 상수의 식별자를 문자열로 저장할 뿐 FK가 아니다.

```java
// com.rookies6.codeguard.scanner.rule.SecurityRule
@Getter
@RequiredArgsConstructor
public class SecurityRule {
    private final String ruleId;                 // "SQLI-003"
    private final VulnerabilityType vulnerabilityType;
    private final String cweId;                  // "CWE-89"
    private final Severity severity;
    private final Set<Language> targetLanguages;
    private final Pattern pattern;               // 탐지 정규식
    private final List<Pattern> excludePatterns; // 오탐 제외 조건
    private final String title;
    private final String description;            // LLM 프롬프트에 함께 전달

    public boolean appliesTo(Language language) {
        return targetLanguages.contains(language);
    }

    public boolean matches(String line) {
        return pattern.matcher(line).find();
    }

    public boolean isExcluded(String line) {
        return excludePatterns.stream().anyMatch(p -> p.matcher(line).find());
    }
}
```

### 5.2 Severity

```java
public enum Severity {
    CRITICAL("치명적", 4, "#DC2626"),
    HIGH("높음",      3, "#EA580C"),
    MEDIUM("중간",    2, "#CA8A04"),
    LOW("낮음",       1, "#65A30D");

    private final String displayName;
    private final int weight;        // 정렬·최고 심각도 산출용
    private final String colorHex;   // 프론트 배지 색상 기준값

    Severity(String displayName, int weight, String colorHex) {
        this.displayName = displayName;
        this.weight = weight;
        this.colorHex = colorHex;
    }

    public String getDisplayName() { return displayName; }
    public int getWeight() { return weight; }

    /** 테스트 파일 탐지 시 1단계 하향 (BR-S007) */
    public Severity downgrade() {
        return switch (this) {
            case CRITICAL -> HIGH;
            case HIGH     -> MEDIUM;
            default       -> LOW;
        };
    }

    /** 취약점 목록에서 최고 심각도 산출 (BR-S014) */
    public static Severity highest(Collection<Severity> severities) {
        return severities.stream()
                .max(Comparator.comparingInt(Severity::getWeight))
                .orElse(null);
    }

    /** 룰 정의를 외부 설정 파일로 분리할 경우를 대비한 문자열 파싱 */
    public static Severity from(String raw) {
        if (raw == null) return MEDIUM;
        return switch (raw.trim().toUpperCase()) {
            case "CRITICAL", "치명적" -> CRITICAL;
            case "HIGH", "높음"       -> HIGH;
            case "LOW", "낮음"        -> LOW;
            default                   -> MEDIUM;
        };
    }
}
```

```java
public enum Language {

    JAVASCRIPT("JavaScript", Set.of("js", "jsx", "mjs")),

    PYTHON("Python", Set.of("py")),

        this.extensions = extensions;

        String lower = ext.toLowerCase();
        return Arrays.stream(values())
                .filter(l -> l.extensions.contains(lower))
                .findFirst()
                .orElse(UNKNOWN);
    }

}
```

### 5.7 LlmVerdict (신규)

LLM이 "룰 탐지가 실제 취약점인지" 판단한 결과. **탐지를 취소하는 값이 아니라 표시용 참고값이다 (BR-L008).**

```java
public enum LlmVerdict {
    TRUE_POSITIVE("실제 취약점",   "룰 탐지가 타당하다고 판단됨"),
    FALSE_POSITIVE("오탐 가능성",  "안전한 코드일 가능성이 높다고 판단됨"),
    UNCERTAIN("판단 보류",         "주변 문맥이 부족해 확신할 수 없음");

    private final String displayName;
    private final String description;

    LlmVerdict(String displayName, String description) {
        this.displayName = displayName;
        this.description = description;
    }

    public String getDisplayName() { return displayName; }

    public static LlmVerdict from(String raw) {
        if (raw == null) return UNCERTAIN;
        try {
            return LlmVerdict.valueOf(raw.trim().toUpperCase());
        } catch (IllegalArgumentException e) {
            return UNCERTAIN;
        }
    }
}
```

## 6. 연관관계 매핑 전략

### 6.1 연관관계 매핑 규칙

| 관계 유형 | 기본 전략 | 이유 | 본 프로젝트 적용 |
| --- | --- | --- | --- |
| **@ManyToOne** | LAZY | 성능 최적화 | 전부 LAZY |
| **@OneToMany** | LAZY + Cascade ALL | 분석 결과는 Root와 생명주기 동일 | `AnalysisRequest→File`, `File→Finding` |
| **@OneToOne** | LAZY | 일관성 유지 | `Finding→LlmAnalysis` (소유자는 LlmAnalysis 쪽) |
| **@ManyToMany** | 사용 금지 | 복잡성 증가 | 사용 안 함 |

### 6.2 연관관계 매핑 전체도

```java
User                     ← (단방향) AnalysisRequest.user      @ManyToOne LAZY
AnalysisRequest          → (양방향) analysisFiles             @OneToMany LAZY, ALL, orphanRemoval
AnalysisFile             → (양방향) findings                  @OneToMany LAZY, ALL, orphanRemoval
FindingVulnerability     → (양방향) llmAnalysis               @OneToOne  LAZY, ALL, orphanRemoval
```

> **단방향으로 둔 곳**: `User → AnalysisRequest`
사용자별 분석 목록은 항상 페이징·필터가 필요하므로 컬렉션 매핑 대신 Repository 조회로 처리한다.
> 

### 6.3 Cascade 옵션 가이드

```java
// 분석 요청 삭제 시 파일·취약점·LLM 결과까지 모두 삭제 (BR-A010)
@OneToMany(mappedBy = "analysisRequest", cascade = CascadeType.ALL, orphanRemoval = true)
private List<AnalysisFile> analysisFiles = new ArrayList<>();

// 사용자 참조는 약한 연결 — cascade 없음
@ManyToOne(fetch = FetchType.LAZY)
@JoinColumn(name = "user_id")
private User user;
```

### 6.4 양방향 연관관계 관리

```java
// AnalysisRequest
public void addFile(AnalysisFile file) {
    analysisFiles.add(file);
    file.assignTo(this);        // 양방향 동기화
    this.totalFiles = analysisFiles.size();
}

// AnalysisFile
public void addFinding(FindingVulnerability finding) {
    findings.add(finding);
    finding.assignTo(this);
}
```

> `assignTo(...)`는 **package-private**으로 선언해 Aggregate 외부에서 연관관계를 임의로 바꾸지 못하게 한다.

## 8. 성능 최적화 전략

### 8.1 N+1 문제 해결

```java
public interface FindingRepository extends JpaRepository<FindingVulnerability, Long> {

    /* 결과 화면: 분석 1건의 취약점 전체 + 파일 정보 한 번에 */
    @Query("""
           SELECT f FROM FindingVulnerability f
           JOIN FETCH f.analysisFile af
           WHERE af.analysisRequest.id = :requestId
           ORDER BY f.severity DESC, af.relativePath ASC, f.startLine ASC
           """)
    List<FindingVulnerability> findAllByRequestIdWithFile(@Param("requestId") Long requestId);

    /* 취약점 상세: LLM 분석까지 함께 */
    @EntityGraph(attributePaths = {"analysisFile", "llmAnalysis"})
    Optional<FindingVulnerability> findWithDetailById(Long id);

    /* 대시보드: 심각도별 집계 — Entity 로딩 없이 통계만 */
    @Query("""
           SELECT f.severity, COUNT(f) FROM FindingVulnerability f
           WHERE f.analysisFile.analysisRequest.id = :requestId
             AND f.status <> 'IGNORED'
           GROUP BY f.severity
           """)
    List<Object[]> countBySeverity(@Param("requestId") Long requestId);
}
```

### 8.2 대용량 컬럼(content, raw_response) 회피

목록 조회에서 코드 본문을 절대 로딩하지 않는다. **DTO Projection**을 기본으로 한다.

```java
public interface AnalysisFileRepository extends JpaRepository<AnalysisFile, Long> {

    /* 파일 트리 렌더링용 — content 제외 */
    @Query("""
           SELECT new com.rookies6.codeguard.dto.FileTreeItem(
                    af.id, af.relativePath, af.fileName, af.language, af.fileSizeBytes)
           FROM AnalysisFile af
           WHERE af.analysisRequest.id = :requestId
           ORDER BY af.relativePath ASC
           """)
    List<FileTreeItem> findTreeByRequestId(@Param("requestId") Long requestId);
}
```

### 8.3 대량 삽입 전략

한 번의 분석에서 취약점 수십 건 + LLM 결과 수십 건이 동시에 저장된다.

| 상황 | 대응 |
| --- | --- |
| 건수 적음 (< 50) | `saveAll()` 로 충분 (MVP 기본) |
| 건수 많음 | IDENTITY 전략은 JDBC batch가 막히므로 `JdbcTemplate.batchUpdate()` 로 전환 |
| 트랜잭션 | 파일 단위가 아니라 **분석 요청 단위**로 커밋해 부분 저장 상태를 방지 |
